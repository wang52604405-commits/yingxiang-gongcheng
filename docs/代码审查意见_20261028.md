## 1. 它是什么

**工程影像管理平台**（产品码 `HDYX`）：面向水利/工程现场项目部的影像采集、归档、编号、打印与云预览软件。

三端一体：

| 端 | 路径/入口 | 作用 |
|---|---|---|
| 桌面局域网服务 | 根目录 `app.py`（约 9100 行）+ `run.py` | 本机/局域网 Flask：工程划分、上传、OCR、整理、批量打印、导出、局域网会话 |
| 云端授权中心 | `server/`（`python -m server.app`） | 账号注册登录、会员授权、微信小程序 API、桌面 sync、管理后台、OSS 中转 |
| 微信小程序 | `miniprogram/`（uni-app Vue3，包名 engineering-image-miniprogram v1.6.4） | 现场拍照、分片/直传、工程成员、删除密码校验 |
| 宣传站 | `website/` | 产品介绍与下载页 |
| 发布链路 | `.github/workflows/deploy.yml` + `deploy_auth.py` + `publish_update.py` | 推 `main` → 回归 → 部署阿里云授权中心 → 本机 5088 → 客户更新包 |

对外 API 域名（文档约定）：`https://api.shuiliyingxiang.cn`。

仓库为 **public**，语言主栈 Python，约 341 个文件；另有大量历史 Codex/ChatGPT 分支。

## 2. 技术栈与入口

### 2.1 技术栈

- **后端**：Flask + SQLite（WAL）+ itsdangerous 令牌 + werkzeug 密码哈希 + cryptography Ed25519  
- **影像**：Pillow、RapidOCR（onnxruntime）、分片上传、OSS（alibabacloud-oss-v2）  
- **桌面打包**：PyInstaller（多个 `.spec`）、Inno Setup（`安装脚本.iss`）  
- **小程序**：Vue 3.4 + uni-app + TypeScript + Vitest  
- **CI**：GitHub Actions（托管 Windows 回归 + 自托管 Windows Runner 发布）  
- **依赖**：根 `requirements.txt` / `server/requirements.txt`（多数未钉版本，仅部分钉了 truststore、gunicorn、oss SDK）

### 2.2 启动入口

```text
run.py
  └─ from app import run_lan_server   # 桌面局域网服务（默认 0.0.0.0:5088）

python -m server.app                 # 云授权中心（开发默认 127.0.0.1:5000）
python -m server.app create-admin …  # 创建管理员

miniprogram: npm run dev:mp-weixin / build:mp-weixin
```

### 2.3 配置与授权

- `album_config.json`：本机 host/port/便携数据目录（已提交仓库）  
- `licensing.py`：客户端内置 **公钥** 验签；私钥仅开发机/服务器  
- `server/config.py`：密钥、微信、OSS、配额全部环境变量化；拒绝占位 `SECRET`  
- `deploy_auth.py`：白名单打包上传、SQLite backup、迁移验证、失败回滚  
- `.gitignore`：已忽略 `*.pem`、`keys/`、`服务器访问-*/`、`data/` 等

## 3. 安全与质量问题清单

### 3.1 严重（优先处理）

| ID | 问题 | 位置 | 说明 |
|---|---|---|---|
| S1 | **硬编码遗留删除口令常量** | `app.py:69` `LEGACY_DELETE_SAFETY_PASSWORD = "***"` | 真实口令字符串进了公开仓库。虽用于「禁止设为新密码」黑名单（约 `5691` 行），但任何能读源码的人已知该历史口令；若旧工程仍以明文形式存过该值，存在绕过风险面。应改为哈希/环境变量，并从仓库与历史中清除。 |
| S2 | **局域网原图/缩略图接口无登录校验** | `app.py:8523-8556` `/photos/...`、`/thumbs/...` | 仅做文件名防穿越，**无 `login_required`**。服务默认绑 `0.0.0.0`（`runtime_host`/`album_config.json`）。同一局域网内知道或枚举到 `project_code`+文件名即可拉原图。公网虽有 `_public_gate`，但局域网场景是主战场。 |
| S3 | **局域网「姓名登录」默认可空门** | `app.py:1170-1234` | `lan_access.json` **未配置密码时直接放行**；登录/注册只校验姓名长度 2–30，任意局域网用户可拿 session。再叠加 S2，照片面几乎敞开。 |
| S4 | **生产基础设施信息写进公开仓** | `deploy_auth.py:28-32` 默认 `SERVER_HOST=root@<公网地址>`；`album_config.json` 含本机路径；`server/mailer.py` 文档示例邮箱；文档/README 含域名与部署路径 | 仓库 **public**。IP、SSH 用户、本机数据路径会降低攻击侦察成本。应改为纯环境变量、示例值，并评估是否改为 private 或拆私密运维仓。归档本文时已去掉具体公网地址，避免新文件再写回仓库。 |
| S5 | **桌面核心仍是超大单体，推 main 即生产** | `app.py` ≈412KB/9100 行；`server/mobile_api.py` ≈317KB/6784 行；`.github/workflows/deploy.yml` `push: main` → validate → deploy-auth → 5088 → 更新通道 | 单文件改一处易牵动上传/打印/云同步；CI 虽有 unittest，但 **无人工批准的稳定通道**（旧产品报告已指出，现状仍在）。回归漏网会直接影响客户更新。 |

### 3.2 一般

| ID | 问题 | 位置 | 建议 |
|---|---|---|---|
| G1 | 根依赖未锁定版本 | `requirements.txt`（flask/Pillow 等无 pin） | 生成 `requirements.lock` 或钉精确版本；CI 用锁文件安装。 |

| G3 | 防篡改可被环境变量跳过 | `tamper_guard.py` `ALBUM_SKIP_GUARD=1` | 打包客户版去掉跳过；仅内部调试通道。 |
| G4 | 客户工程名/路径硬编码残留 | `server/mobile_api.py:39` `DEFAULT_PROJECT_NAME=邯郸市…龙泉缓洪…`；`app.py:66` 默认 `E:\龙泉缓洪工程施工照片` | 改为空默认或通用占位，避免新装露出他人工程品牌。 |

## 5. 迭代计划

### 第一轮（安全止血，1–3 天）

1. **移除/轮换** `LEGACY_DELETE_SAFETY_PASSWORD` 明文：改为不可逆指纹常量或配置；扫描历史工程数据是否仍用该口令并强制重置。  
2. **给 `/photos`、`/thumbs`、必要时 `/originals` 加登录或签名 URL**；未登录返回 401。  
3. **默认强制局域网访问控制**：未配置 `lan_access` 时拒绝非本机写操作（或首次启动向导强制设口令）。  
4. **脱敏公开仓**：`deploy_auth.py` 去掉默认公网 IP；`album_config.json` 改为 `album_config.example.json` 并不再提交真实路径；mailer 注释改占位。  
5. 补 3～5 条安全负向单测（未登录媒体、空 lan 口令、删除口令黑名单）。  
6. **不改业务功能面**；合入前跑 `unittest` + compileall。  
   - 全量 Windows 回归、staging E2E：**需 CloudAgent 真跑**（授权恢复后可用 CloudAgent 真跑；本导出仍为静态审查结论）。

### 第二轮（结构与供应链，约 1–2 周）

1. 拆 `app.py` / `mobile_api.py` 边界，保持路由兼容。  
2. 钉死 `requirements*.txt` / 小程序 lock，加 `pip-audit`。  
3. 发布流水线加 environment protection / 人工批准稳定通道。  
4. 清理废弃远程分支；评估仓库改 private 或拆 `ops` 私仓。  
5. 统一 CI Python 版本；补局域网鉴权与媒体 ACL 的集成测试。

### 第三轮（产品化与真机，约 2–4 周）

1. 真机：微信正式域名、OSS 双桶、桌面 5088 升级、打印导出回归 → **需 CloudAgent / 自托管 Runner 真跑**。  
2. 订单/退款/协议等商业闭环（对照旧 `产品全面审查报告.md` P0-07/09）。  
3. Authenticode 签名与更新通道 HTTPS 验收。  
4. 可观测性：错误中心、备份恢复演练按钮化。

## 7. 结论（给负责人）

这是一套 **已上线演进中的工程影像 SaaS + 桌面局域网归档** 产品，云端鉴权与移动上传契约整体认真，部署回滚意识强，测试资产厚。

当前静态审查下，**最阻发布的不是缺功能，而是公开仓里的遗留口令常量、局域网媒体未鉴权、以及可选为空的局域网门禁**——三者叠在默认 `0.0.0.0` 绑定上，现场局域网风险偏高。建议先做完第一轮再谈新功能迭代。

**严重 Top5：S1 硬编码删除口令 → S2 媒体无登录 → S3 局域网空门禁 → S4 公开仓基础设施暴露 → S5 超大单体 + 推 main 即生产。**
