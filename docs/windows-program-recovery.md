# Windows 程序发布与失败恢复

本流程只更新已安装且健康的正式程序。`deploy_prod.ps1` 不把在线数据检查点当作
程序回滚目标，不恢复 `D:\工程影像资料` 或其中的 `mobile_sync_state.json`。
初次安装、无法核实旧版本或程序快照不完整时，会在停止旧程序之前拒绝发布。

## 构建与程序快照

构建在 `RUNNER_TEMP`（缺省为系统临时目录）下的新建独立 Python 环境中完成。
依赖安装、打包、签名和验签均使用该环境，不修改原 Python 的包。临时目录及基础
解释器不能通过链接落入程序或业务资料目录；临时卷至少须有 3 GiB 可用空间。
构建环境保留并记录位置供排查，不属于生产数据备份；后续空间不足会提前停止。

停止旧程序前，发布器核对旧服务健康响应、版本、唯一监听者、安装路径和进程
创建时间，然后建立程序专用快照。快照只包含：

- `album_server.exe`
- `工程影像管理平台.exe`
- `guard_manifest.dat`
- 完整 `_internal` 运行目录

`license.dat`、业务数据库、照片、同步状态、配置、日志及其它安装目录文件不在
白名单内。快照独占创建，保存版本、目录身份、完整文件清单和 SHA-256；复制前后
再次核对运行目录，程序文件变化时拒绝继续。目录链接、Windows junction/reparse、
硬链接、程序与资料目录重叠，以及不支持可逆重命名的跨文件系统布局也会拒绝。
空间校验包括快照、待发布程序和恢复暂存所需空间，并额外保留 256 MiB。

## 失败后的恢复

只有快照校验和旧版本复核通过后，发布器才停止目标程序。被替换的程序文件会保留
在快照中的专用目录，随后复制并验证新程序、启动服务，再核对新版本和实际监听者。

从首次尝试停止旧程序开始，脚本可捕获的停止、替换、启动或健康检查异常均进入恢复路径。
恢复只停止重新核实身份的本程序进程，不终止外部端口占用者；随后校验程序快照，
恢复白名单程序文件并启动保存的旧版本。只有旧版本及其监听进程身份核实成功，
才报告“发布失败，旧程序已恢复”；发布任务仍以失败结束，后续更新通道发布不会继续。

文件恢复先完成校验和暂存，再通过可逆重命名切换。失败程序及恢复中断的程序都
保留在快照内。部分文件切换失败时会逆向放回切换前的实时程序；如果逆向恢复或
旧版本健康检查也失败，会明确报告恢复未确认及证据路径，不会声称恢复成功。
辅助工具 `desktop_program_snapshot.py` 的 CLI 供此事务调用，不能跳过停服和版本
核查，单独执行 `restore` 来替代完整恢复流程。

隔离回归由 `test_desktop_program_snapshot.py` 验证真实文件的快照、校验、可逆
恢复和失败保留；`test_deploy_program_recovery.py` 验证 PowerShell 的阶段编排、
旧版本核查、外部监听者拒绝和恢复失败提示。`test_desktop_recovery_roundtrip.py`
进一步将真实 PowerShell 复制及恢复流程接上实际 Python 工具，在快照完成后新增
SQLite 记录、原片和同步状态，再注入复制、启动及健康检查失败，确认只退程序。
`test_deploy_build_isolation.py` 在离线 venv 中安装测试包，校验原环境包及元数据
不变。测试不执行正式 EXE、WMI 启动、生产服务操作或任何在线资料覆盖。

## 数据检查点的用途

2026-11-18 父线程独立校验了服务器在线检查点及桌面资料副本：数据库完整性检查
通过；服务器 3699 个文件、桌面 44044 项在复制前后与副本哈希一致。桌面同步中的
唯一变化状态文件另保存并校验了补充副本。这些是已校验的在线检查点，不是全体
文件在同一时刻的原子快照。

正常程序发布失败必须保留实时资料及发布后新增内容，不把检查点整体覆盖回来。
若以后确需灾难恢复，应另行冻结写入、核对数据库与影像关联、处理同步状态，并
明确恢复范围；不能自动套用程序回滚流程。本轮只在隔离目录与模拟服务中验证，
没有进行生产恢复演练、合并或部署。
