# 工程影像微信小程序 V1 开发蓝图

> 更新日期：2026-08-25
> 代码基线：`origin/main@b5a5924878bfcdfb30de0b6d1c47254da5791f19`
> 产品版本：`A20260822-2.64`
> 开发分支：`codex/wechat-miniapp-v1`

## 1. 产品目标

首版供用户本人试用，完成以下真实闭环：

```text
首次绑定现有云账号
→ 微信一键登录
→ 选择邯郸市永年区洺河龙泉缓洪工程
→ 指定单元或自动匹配
→ 拍照/相册
→ 原图持久保存到本机队列
→ 原图临时上传服务器
→ 服务器生成 100KB 预览供影像库查看
→ 对应电脑下载原图、自动归档并回执
→ 服务器清理原图中转对象，永久保留预览
```

用户提供的 `00 / 10 / 20 / 30 / 90` 是开发阶段，不是软件导航，绝不进入产品界面。唯一活动界面基线为第二版：`工作台｜影像库｜[上传]｜待上传｜我的`。

首版包含上传与查看，不包含手机端上传后的编辑、删除、审核退回、打印和 PDF；这些继续由电脑端承担。

## 2. 业务语义

- 工程层级：合同工程 → 单位工程 → 分部工程 → 单元工程 → 可选工序。
- 工程影像只有 `construction`（施工）和 `supervision`（监理）两类。
- 其它影像是独立目录树，继续使用 `_other_image` 语义，禁止新增 `category=other`。
- 当前 888 个单元及 YNLQ 编码不变；333 个带工序的单元在选择归属时渐进显示工序。
- 新增永久 `photo_uuid` 作为跨端主键；显示编号和文件名仍允许因桌面排序而变化。

## 3. 客户端技术与图片规则

- 传统 uni-app Vue3 + TypeScript，固定 2026-08-13 的 Vue3 发布组合，不使用 uni-app x。
- 微信端相机、文件系统、上传、权限和 custom-tab-bar 放在平台适配层；业务状态机和页面保持可复用。
- 第二版界面使用自定义底栏实现中央上传按钮；高频操作无装饰动画，按压反馈 `scale(.97)`，所有过渡小于 300ms，只改变 transform/opacity，并支持 reduced-motion。
- 相册单次最多选择 20 张；上传并发固定为 2。
- 微信 `uploadFile` 的大文件能力不能承诺 50MiB 单请求：客户端只对 `<=8MiB`
  使用直传，较大原图切成固定 4MiB 分片，按服务器返回的 `uploaded_chunks`
  断点补传；单张原图总上限仍为 50MiB。

每张原图上传必须满足：

1. 读取方向、尺寸、拍摄时间等元数据；
2. 保留静态 JPEG/PNG 原字节，不把 PNG 伪装成 JPG；单文件不超过 50MiB；
3. 复制到微信用户文件目录，再写入队列清单；
4. 上传原图 SHA-256、实际大小、原文件名、方向和拍摄时间；
5. 服务器流式读取并完整解码，校验格式、SHA、大小、像素数与最长边；拒绝动图、HEIC、WebP、GIF；
6. 服务器从原图生成永久 JPEG 预览：最长边先限制为 1920px，在质量 30–90 内寻找最高可用质量，仍超过 `102400` 字节则每轮缩小 15%。

手机原图只作服务器到目标电脑之间的临时中转：移动接口永远只返回 100KB 预览，电脑成功落盘并回执后服务器删除中转原图。电脑既有原图保持原样；渐进回填只上传 `<=102400` 字节 JPEG 预览。

## 4. 离线与状态

本机持久队列硬上限 160MB。网络恢复或小程序回到前台时续传；微信进入后台后可能中断的请求必须回到可重试状态，不能显示为成功。

```text
local_ready -> uploading -> server_saved
server_saved -> analyzing -> needs_review
server_saved/needs_review -> desktop_pending -> desktop_imported
desktop_imported -> original deleted | cleanup_pending
任一可重试阶段 -> failed -> 原阶段
```

批次使用 `client_batch_id`，单图使用 `photo_uuid`。任何网络重试均由服务器幂等返回已有资源，不能重复入库。

## 5. 服务器与云存储

- 现有 Flask + SQLite 继续作为单人试用后端；新表全部按 `account_id` 隔离，并采用幂等增量迁移。
- OSS 分成两个北京地域私有 Bucket：原图中转 Bucket 开启服务端加密、关闭版本控制并设置短期生命周期兜底；永久预览 Bucket 开启服务端加密和版本控制、不配置自动删除。禁止共用单一版本化 Bucket，否则普通 delete 只产生删除标记，旧版原图仍会长期存在。
- 小程序 API/Upload 访问 `api.shuiliyingxiang.cn`，nginx 请求体上限 52MiB，总原图硬上限 50MiB、直传端点硬上限 10MiB；nginx 上传 connect/read/send 为有限 240 秒，gunicorn 为 300 秒。两个 Bucket 均不公开，地址均短时签名。
- OSS 预览是直签 HTTPS URL；微信 downloadFile 合法域名除 API 域名外，必须加入正式预览 Bucket 实际主机或预览自定义域名。该主机只能在 Bucket 创建后确认，是真机发布阻塞项；原图 Bucket 主机仅桌面端使用。
- 服务器使用 ECS RAM 角色，不在仓库、安装包、日志或记忆库保存 AccessKey、AppSecret、密码。
- OCR/自动匹配为独立单并发后台任务；POST 只快速返回 202 job，前台轮询状态。并发重试只复用一个 job；新进程启动时立即把旧进程遗留任务转人工确认，运行中的 job 由独立周期心跳续租，单张 OCR 过慢也不会被误判。失败或低置信度时不丢照片、不静默错挂。
- 分片临时区按账号/批次/UUID/冻结目标机器隔离，逐片与整图双重 SHA 校验；具有 TTL、每账号/全局会话数与预留字节配额。完成、失败、取消和过期均清理；清理失败持久标记 `pending`、后续请求周期重试，并继续占用配额以阻止磁盘无界增长。

移动端与桌面端的权威路由、字段和状态见 [移动端API-v1.md](./移动端API-v1.md)。

## 6. 电脑端适配

- 启动时及每 30 秒同步工程快照和手机收件箱。
- 桌面登录令牌调用 `/api/activate`后保存机器限定 `desktop_sync_token`，桌面同步和原图下载必须使用它；普通登录令牌和微信 `mobile` 令牌都无权访问桌面 v1 接口。
- 快照包含工程根、完整单元层级、工序、其它影像树、版本号和当前账号 active 的 `desktop_machine_id`。创建批次时固化目标机器，工程后来由其它电脑同步也不改投旧批次。
- 手机照片按工程/其它影像、施工/监理、单元/工序导入；相同 `photo_uuid` 永不重复导入。
- 服务器保存后手机显示“电脑待归档”；只有账号和目标机器同时匹配的 inbox 才返回原图地址。桌面先校验 SHA、按原字节落盘，再回执“电脑已归档”。
- 回执先落 `desktop_imported` 再清原图；清理失败记录 `cleanup_pending`，重复回执只重试清理，不重复导入。永久预览不删除。
- 既有照片 JPEG 查看副本渐进上传，可暂停、续传且严格 `<=102400` 字节；本地原图和当前编号不改变。

## 7. 安全实施顺序

1. 每次开工先 `git fetch`，比较本地、远程提交和产品版本；远程更新时从远程最新版本继续。
2. 所有工作在 `codex/wechat-miniapp-v1` 完成；`main` 的现有自动生产部署不用于试验。
3. 数据迁移前备份服务器 SQLite、服务器代码、工程配置和全部相册 metadata，并记录校验值。
4. 先使用独立测试数据库、测试对象前缀和测试桌面数据副本。
5. 通过测试后生成微信体验版；用户验收前不合并 `main`、不提交正式微信审核。

## 8. 验收标准

- 旧的 8 项桌面/服务器测试全部通过，迁移前后现有账号、授权、工程记录数量不变。
- 原图 JPEG/PNG `<=50MiB`，`<=8MiB` 直传、较大图 4MiB 分片断点续传，永久 JPEG 预览逐张 `<=102400` 字节；乱序分片可恢复、重复片不重复写，不同哈希冲突，损坏、超像素、动图、HEIC/WebP/GIF、伪造格式、错误 SHA/大小均被拒绝。
- 飞行模式连续保存 80 张，关闭再进入微信后数量不丢；恢复网络后无重复上传。
- 施工、监理、单元工序和其它影像均正确归档；低置信结果必须人工确认。
- 电脑离线时服务器临时保存原图与永久预览；目标电脑恢复后只导入一次，回执后原图被清理。模拟删除失败时状态为 `cleanup_pending`，重试后完成且预览仍可查看。
- Android 与 iPhone 微信真机覆盖深浅色、权限拒绝、切后台、令牌过期、服务中断和 OSS 故障。
- 自动匹配在回执前优先读原图做 OCR；代表性水印文本一致度不低于 95%。
